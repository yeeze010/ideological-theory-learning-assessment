# 部署方案

## 环境规划

| 环境 | 用途 | 数据策略 |
|---|---|---|
| local | 开发自测 | Docker Compose 本地依赖 |
| dev | 联调环境 | 可重置数据，保留样例数据 |
| test | 测试验收 | 接近生产配置，定期刷新 |
| prod | 正式环境 | 严格备份、审计、权限隔离 |

## Docker Compose 组件

- `web`：构建 Vue 静态资源，由 Nginx 提供访问。
- `api`：NestJS 服务，暴露 `/api/v1` 和健康检查。
- `postgres`：业务数据库，挂载持久化卷。
- `redis`：缓存、队列、会话状态。
- `minio`：课程附件、证书、学习报告对象存储。
- `nginx`：HTTPS、反向代理、静态缓存、上传大小限制。

## Nginx 策略

`/` 指向前端静态资源，`/api/` 反向代理到后端服务，`/files/preview/` 通过后端签名授权后访问 MinIO。生产环境启用 HTTPS、HSTS、Gzip、静态资源缓存和上传体积限制。

## 发布流程

1. 合并到 `develop` 后自动部署 dev。
2. 里程碑验收通过后合并到 `main` 并打 tag。
3. 生产发布前执行数据库迁移、备份、健康检查和回滚预案确认。
4. 发布后监控 API 错误率、登录成功率、考试保存延迟、MinIO 上传失败率。

## 备份恢复

PostgreSQL 每日全量备份，关键考试期增加增量备份；MinIO 开启对象生命周期与版本策略；Redis 不作为唯一数据源，队列任务需支持幂等重放。
