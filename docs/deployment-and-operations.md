# 部署与运维方案

## 1. 环境划分

| 环境 | 用途 | 说明 |
| --- | --- | --- |
| `dev` | 本地开发 | `npm` 启动或 `docker compose up` |
| `test` | 集成测试 | 验证接口、前端联调、验收预演 |
| `staging` | 预发验证 | 模拟生产配置，演练发布与回滚 |
| `prod` | 正式环境 | 仅通过验收版本发布 |

## 2. 本地部署组成

`docker-compose.yml` 已规划以下服务：

- `postgres`
- `redis`
- `minio`
- `api`
- `web`

## 3. 运维基线

- 数据库每日备份，保留最近 7 日与最近 4 周快照。
- MinIO 对象存储每日增量备份。
- Redis 仅存放可重建缓存和临时答题态，不作为唯一事实来源。
- Nginx、API、数据库错误日志保留至少 30 天。

## 4. 发布流程规划

1. 开发分支合并后触发 CI。
2. `develop` 分支完成测试环境构建验证。
3. `release/*` 分支进入预发环境验证。
4. 验收通过后将发布候选合并到 `main`。
5. 打版本 tag，归档测试报告、部署记录和验收材料。

## 5. 回滚方案

- 应用回滚：切回上一版镜像或上一版静态资源。
- 数据回滚：仅在评估兼容性后执行迁移回退或备份恢复。
- 文件回滚：恢复 MinIO 备份快照并核验对象索引。

## 6. 当前缺口

- 未配置自动部署流水线。
- 未提供数据库迁移脚本与备份恢复演练记录。
- 未提供健康检查、告警和日志采集落地实现。
